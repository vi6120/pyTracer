A green test does not mean your fix worked.

Agents are nondeterministic. Re-run a failed one and the model and tool responses come back different every time, so a green test might mean your change worked, or might just be the model drifting.

pyTracer holds those responses frozen and replays the exact run, so the failure reproduces on demand instead of by luck.

Capture

Record the run, down to each model call and tool result, stamped with branch and commit.

Freeze

Pin the recorded responses as mocks, along with the clock, timestamps, UUIDs and RNG.

Replay

Re-run on any branch in full, partial or live mode, or freeze all but the step you changed.

Classify

Get a fixed, still-failing or diverged verdict, or no verdict with the reason why.

A verdict, not a lucky green run.

A verdict is only drawn from a run that stayed on its recording. If a branch makes a call the recording cannot serve, you get cannot judge with that call named, never a lucky fixed. If the baseline itself drifts, it is cannot reproduce.

A branch that fails exactly as before is still failing, whatever else changed. That is the question pass/fail cannot answer: did my change fix it, or break something?

Questions, answered.

How is pyTracer different from tracing or eval tools?
Tracing shows you that a run happened; eval scores an output. pyTracer freezes a captured run and re-runs it deterministically on another branch, so you learn whether your code change is what fixed the failure. See the full comparison.
What does deterministic replay actually mean?
The recorded model and tool responses are injected back in during replay, so the agent follows the exact same path with no live API calls. The same failure reproduces identically every time.
Do I have to change my agent code?
With a framework adapter, no: register it and the model and tool calls are captured and replayable as they are. Otherwise add the @op decorator to the functions that call models and tools, one or two lines each.
Is it open source? Can I self-host?
Yes to both. The client toolchain is Apache-2.0 and the server components are AGPL-3.0; all 12 packages are on PyPI. Self-host the gateway and stores as a Docker stack, or point the SDK at the hosted gateway.
