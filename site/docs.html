What pyTracer is

pyTracer is an agent test and replay platform. It captures what an AI agent does (its LLM calls, tool calls, reasoning steps, and handoffs), replays a past run deterministically by injecting the recorded responses instead of calling live services, and regression-tests agents in CI. Its headline capability is cross-branch reproduction: take a captured failing run and re-run it against a different branch with the model version and recorded tool responses held frozen, so you learn whether a branch actually fixed the bug.

Requirements

  • Python 3.10 or newer (3.12 recommended).
  • Nothing else to just instrument and replay locally.
  • For capturing to a gateway and browsing traces: a running pyTracer gateway with its stores (ClickHouse, PostgreSQL, Redis), self-hosted or the hosted service.

Installation

Install the whole platform, or just the SDK in your agent:

# the whole platform
pip install pytracer-all

# or just the client SDK
pip install pytracer-sdk

# the CLI, with the extras you need
pip install pytracer-cli[stores]   # browse/record traces
pip install pytracer-cli[runner]   # cross-branch reproduce

Quickstart (no services)

You can run the whole loop locally with no gateway or database, using an in-memory transport. This instruments an agent, captures its run, and replays it.

import pytracer_sdk as pytracer
from pytracer_sdk import SpanKind

sink = pytracer.InMemoryTransport()
pytracer.configure(sink, service_name="researcher", branch="main", commit="quickstart")

@pytracer.op(kind=SpanKind.TOOL, tool_name="search")
def search(q): return [f"doc about {q} #1", f"doc about {q} #2"]

@pytracer.op(kind=SpanKind.AGENT, agent_name="researcher")
def run(task): return "Summary: " + "; ".join(search(task))

print(run("climate change"))
pytracer.flush()
print(f"captured {len(sink.spans)} spans")

A complete, runnable version lives in the repository under examples/quickstart.

1. Instrument your agent

Add @op to the functions that call models and tools. This is one or two lines per function and does not change their behavior.

import pytracer_sdk as pytracer
from pytracer_sdk import SpanKind

@pytracer.op(kind=SpanKind.TOOL, tool_name="search")
def search(query: str) -> dict:
    ...  # your real tool

@pytracer.op(kind=SpanKind.LLM)
def call_model(prompt: str) -> str:
    ...  # your real model call

@pytracer.op(kind=SpanKind.AGENT, agent_name="researcher")
def run(task: str) -> str:
    return call_model(str(search(task)))

Capture is fire-and-forget: it never blocks your agent, and if the gateway is unreachable your agent keeps running.

2. Ship spans to a gateway

Point the SDK at your gateway so spans flow into the trace store. Stamp each run with the branch and commit so a captured failure is tied to exact code. Use an https:// endpoint in production.

pytracer.configure(
    pytracer.HTTPTransport("https://gateway.pytracer.com", api_key="YOUR_PROJECT_KEY"),
    service_name="researcher",
    branch="main",
    commit="abc123",
)

3. Turn a failure into a test

When a run fails, browse recent captured runs and scaffold a test from one, with no hand-writing of files. These commands need the store client (pip install pytracer-cli[stores]).

pytracer traces list --failed           # find the failing run
pytracer traces show <trace_id>          # inspect its span tree
pytracer record <trace_id> --agent myapp.agents:run --entry task="summarize the doc"

record writes the trace's spans to JSONL and creates a collection: a small YAML file naming the agent to run, the recorded trace to mock from, and the assertions that should hold.

# tests/collection.yaml
name: captured-suite
scenarios:
  - name: summarize-happy-path
    agent: myapp.agents:run          # import path "module:callable"
    entry: { task: "summarize the doc" }
    trace: traces/summarize.jsonl    # the recorded spans
    mode: full                       # full | partial | live
    assertions:
      - { type: no_errors }
      - { type: contains, needle: "summary" }

4. Run a collection

Replays inject the recorded tool and model responses, so the run is deterministic and touches no live services.

pytracer run tests/collection.yaml

Replay modes: full (recorded model and tools), partial (recorded tools, live model), and live.

5. Gate branches in CI

Add the GitHub Action (see packages/cli/ci/github-action.yml). On every pull request it runs the collection and posts a pass/fail summary as a PR comment, failing the check if any scenario regresses. On a push it also auto-documents failures as deduplicated GitHub issues. A GitLab template is included too.

pytracer run tests/collection.yaml --json results.json
pytracer issues sync results.json --repo owner/name   # needs a GitHub token

6. Reproduce on any branch

When a teammate opens a fix, re-run the failing collection against their branch with the mocks frozen, so only the code changes. Needs the runner (pip install pytracer-cli[runner]).

pytracer reproduce --branch feature/fix-bug --baseline main \
  --collection tests/collection.yaml

It checks out each ref in its own isolated workspace, replays, and prints a per-scenario verdict of fixed, still failing, or diverged (a new, different failure), exiting non-zero unless every scenario is fixed.

Framework adapters

Instead of manual @op decorators, drop in an adapter for your framework and its LLM/tool/agent steps are captured automatically:

pip install pytracer-langgraph        # LangGraph / LangChain
pip install pytracer-openai-agents    # OpenAI Agents SDK
pip install pytracer-crewai           # CrewAI
pip install pytracer-autogen          # AutoGen

Self-hosting the gateway

Use cases

Regression-test a customer-support agent

Capture real conversations, turn the ones that went wrong into a collection, and run it on every pull request so a prompt or tool change can't silently reintroduce the same failure.

Prove a fix actually works

A user reports a bug. Capture the failing run, then use pytracer reproduce to re-run it against the fix branch with the model and tools frozen, so you know the code change is what fixed it, not luck.

Compare model or prompt versions deterministically

Freeze the tool responses and replay in partial mode against a new model or prompt, isolating the effect of that one change.

Share test suites across a team

The registry turns collections into versioned, forkable, access-controlled artifacts with pull requests and discovery, the way Postman collections worked for API testing.
