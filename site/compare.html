Why pyTracer

Tracing shows you the failure. pyTracer proves your fix.

pyTracer is the test-and-replay layer for AI agents. Tracing and eval tools show you what happened and score an output; pyTracer freezes a captured run and re-runs it deterministically on another branch, so you learn whether your change is what fixed the failure - not just that today's run happened to pass.

The real problems we address

These are the pains teams building agents actually hit (several confirmed directly in customer interviews):

  • Multi-agent failures are hard to reproduce. One agent's output is the next one's input, and a single missing field silently breaks a downstream step. pyTracer freezes the exact run and replays it, so the failure reproduces on demand instead of by luck.
  • Tracing can't replay. Langfuse, LangSmith, and MLflow show the trace per step, but you can't re-execute it - so you fall back to hand-rebuilding state and injecting it into a node. pyTracer replays the recorded run with the model and tool responses frozen, no manual reconstruction.
  • You're never sure the fix worked. Re-running live returns different model and tool outputs, so a green run might just be drift. pyTracer holds those responses frozen and reports fixed / still-failing / diverged per scenario across branches.
  • Testing agents before merge is manual. Teams keep a few golden examples and test by hand. pyTracer turns a captured failure into a runnable regression test that gates CI - and runs inside your existing pytest suite.
  • Retries and their cost are invisible. When a validator retries the model, tracing shows only the last attempt. Full retry-chain capture (every attempt and the wasted spend) is on our roadmap.

Why teams choose pyTracer

  • Executable, deterministic replay with frozen tool responses - the one thing the tracing and eval tools above do not document. Your captured run becomes a test you can run anywhere, with no live calls and no flakiness.
  • Cross-branch reproduction with a clear verdict. Re-run the exact failure on a fix branch and get fixed / still-failing / diverged - a direct answer to "did my change fix it?"
  • Open core, no lock-in. Apache-2.0 client toolchain and an AGPL server you can self-host. The full replay engine, including the fidelity work, is open source.
  • Fits your stack. Adapters for LangGraph, CrewAI, AutoGen, and the OpenAI Agents SDK; a CI gate and PR trigger; and a pytest plugin so agent tests live beside your unit tests.

Where we sit in the wider landscape

The agent-tooling market clusters into four jobs. We track the whole field; here is its shape and where deterministic replay fits.

Observability and tracing

Show you what happened in production, step by step. They surface the failure; they do not re-run it.

Evaluation and scoring

Grade how good an output is with metrics or an LLM judge, usually by re-running the app live, so the score moves when the model or tools drift.

Gateways and proxies

Route, cache, guardrail, and budget model traffic. Caching cuts cost; it is not a deterministic test.

Simulation

Probe an agent with synthetic multi-turn scenarios. It generates new situations; it does not reproduce the exact one that broke.

Deterministic replay, where pyTracer sits

We re-run the exact captured run with the model and tool responses frozen, reproduce it across branches, and return a verdict. The closest-sounding features elsewhere (Phoenix "Span Replay", Laminar "session replay") re-invoke a call live or play a session back visually; neither freezes tool responses for a deterministic regression.
